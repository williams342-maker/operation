# Crafters Market — Modernized Homepage + Full Marketplace

## Original Problem Statement
> "look at my current website craftersmarket.org make it more modern and dynamic"

User selected: **Bold editorial / industrial** aesthetic. Scope expanded into a full multi-vendor marketplace with maker portal, admin console, community hub, AI assistant, 3D viewer, transactional emails, and Stripe payouts.

## Architecture
- **Backend:** FastAPI + Motor (async MongoDB), modular routers under `/app/backend/routers/`.
  - `catalog`, `seo`, `checkout`, `maker`, `stripe_connect`, `admin`, `ai`, `community`.
- **Frontend:** React 19 + React Router + Tailwind + Framer Motion + react-fast-marquee + @google/model-viewer.
- **Theme:** Anton/JetBrains Mono dark industrial (`#0a0a0a` / `#ff4500`).
- **Payments:** Native `stripe` SDK (15.0.1) for Connect Express + Checkout Sessions; `emergentintegrations` StripeCheckout for webhook verification.
- **AI:** Emergent LLM Key (Claude Sonnet 4.5) with per-session transcript replay for memory.
- **Auth:** Magic-link (`itsdangerous`) for makers/admins/buyers; JWT for sessions.

## Collections
products · makers · reviews · blog_posts · custom_orders · maker_applications · activity_events · payment_transactions · ai_chats · download_unlocks · maker_payouts · community_users · community_messages · community_threads · community_files

- ✅ **Duplicate founder_number bug fix + repair endpoint (iter326, 2026-06-03):** User reported on craftersmarket.org that two new makers shared founder slot numbers with existing seeded Founders (#001 Gracious Providence ↔ #001 Iron & Oak Studio, #002 Mimsy's Place ↔ #002 MetalArt Pro Shop). Root cause: `POST /api/admin/seed/featured-content/install-fixture` upserts seeded makers with hardcoded `founder_number: 1..15` from `data/featured_seed_fixture.json` but never bumps `platform_meta.founder_counter` to match. On production, the counter stayed at 0 after the fixture install; the next 2 live promotions started at 1 → collided.
  • **Preventive fix**: `install_featured_seed_fixture` now bumps the counter via `db.platform_meta.update_one({"key": "founder_counter"}, {"$max": {"value": max_seed_number}}, upsert=True)` — atomic, idempotent, never lowers an already-grown counter.
  • **Corrective fix**: new admin endpoint `POST /api/admin/founders/repair-numbers` (with `dry_run: bool`) scans all `tier="founder"` makers, groups by `founder_number`, and for each duplicate group keeps the OLDEST maker's number while reassigning newer collisions to fresh sequential numbers. Also rewrites the matching `activity_events.id` (format `founder-{slug}-{N}`) and patches the human text so the live ticker stays in sync. Bumps the counter to the new max at the end.
  • Tests: **3/3 pass** in `tests/test_iter326_founder_number_repair.py` (dry-run returns plan without mutating DB; apply renumbers newer collision, keeps older, rewrites activity event id; counter bump via `$max` is idempotent).
  • **Production runbook**: After redeploying, the operator should: (1) POST `/api/admin/founders/repair-numbers` with `{"dry_run": true}` to preview the renumber plan, (2) inspect `proposed_changes` to confirm the right makers get bumped, then (3) POST again with `{"dry_run": false}` to apply. Endpoint is admin-auth-gated and idempotent — re-running after a successful repair is a no-op.
